# Gotchas

- Public documentation cannot use the private-repository runner group or its cleanup hooks. Its dedicated hosted workflow publishes the existing guides through MkDocs; the lowercase URL mapping belongs in `scripts/docs_site.py`, while Markdown links keep the original source paths. Keep strict link checks and the project-path HTTP tests enabled so missing setup-guide links or root-relative assets cannot silently reach Pages.
- A Docker image digest and a UA semantic version are related but not interchangeable. Execution trusts the digest; UI and release notes show the version.
- A private GHCR image requires Docker-level authentication; public images do not. Tauri does not receive GitHub tokens.
- Finder and Login Items do not reliably inherit a shell PATH. Docker lookup must retain the standard absolute Docker Desktop locations.
- Embedded Web Chat and a normal browser have separate cookie jars, so a user may sign in separately in each surface.
- `NETWORK_PUBLIC_ORIGIN` intentionally omits the port because UA receives the translated public web port separately.
- The Web Chat webview is remote content even though it is on loopback. Never add it to a Tauri capability.
- A selected workspace is a read/write Docker bind mount. macOS privacy controls and the Colima/Docker Desktop file-sharing policy can still deny it even after native folder selection.
- Codex can store subscription credentials in the macOS Keychain. UA import needs a file-backed `auth.json`; use Codex's file credential-store option instead of copying a token by hand.
- The Codex source file is mounted only in the network-disabled, one-shot importer. UA's long-running container uses the imported credential store under `/data/auth` and is independent of the source afterward.
- UA versions come only from `compatible-runtimes.json`; `runtime-lock.json` must not name a version or image (loading refuses it), so the two files cannot disagree. An update may replace only the exact running selection. Unlisted drift fails closed unless the person opts into unchecked versions.
- CI can produce a universal macOS bundle without release credentials, but that does not make it notarized or suitable for normal distribution.

- Codex onboarding tests require credentials before `instance_config.yaml` exists. The pinned UA 0.4.2 CLI importer requires that config, and its bundled example has an older schema. Desktop uses the reviewed, config-independent UA import function in `runtime-lock.json`; do not restore a post-onboarding import gate. Verify that invocation against each new runtime digest with `rtk proxy python3 tests/runtime_import_smoke.py`.
- Tauri macOS packaging requires Apple's `/usr/bin/xattr`. A Python or pyenv `xattr` earlier on PATH can fail on recursive attribute cleanup. Put `/usr/bin:/bin:/usr/sbin:/sbin` first on PATH for the build process.

- UA 0.4.2's Codex onboarding connection test does not pass the instance root to credential resolution. Set `OPENAI_CODEX_AUTH_STORE_PATH` from the locked store path on the runtime container; importing into `/data/auth` alone is insufficient. The real-image smoke test exercises this provider-test path with only the network transport mocked.

- WKWebView popup creation must reuse the originating `WKWebViewConfiguration`; Tauri's `window_features` supplies it. Allow `about:blank` through navigation policy for deferred login popups, and return an unprivileged child window for same-origin pages. Test with `rtk proxy cargo run -p universal-agents-desktop --example popup_smoke` on macOS.
- The ready runtime redirects `/` to `/docs/`. Launch chat at `/webchat`; keep the onboarding root and docs route separate in the runtime lock.
- WKWebView can suppress `_blank` anchor clicks before calling its new-window delegate. The embedded-page link adapter routes those clicks through `window.open`, clears the opener, and preserves `noreferrer`; native policy still decides where the URL can open.
- Because the adapter opens `about:blank` first and navigates afterwards, a link that leaves the app used to leave an empty white window, the same size and title as the Web UI window and on top of it. UA's credential form ("Open secure credential form") hit this: it is served by UA's secure broker on its own port (18600), not the Web UI port, so it counted as external. The broker port now opens in an app window, and a child window whose first navigation goes to the browser is closed. The popup probe checks both, using a recording hook instead of the real browser.

- WebKit (the macOS window) does not give a button focus when it is clicked, so `document.activeElement` stays on the page. A dialog that "returns focus to what opened it" must remember the clicked control from the click event (`event.currentTarget`), not `document.activeElement`, or focus returns to whatever was focused earlier (the native suite caught it returning to the logs' Expand button).
- The intro and `app.js` both listen for keys on `document`. A dialog that the intro's dismissal opens (the first-run always-on notice) is already showing when the same Escape reaches `app.js`, so it would close at once. The intro calls `preventDefault()` on the keys it handles, and the `app.js` Escape handler ignores events with `defaultPrevented`.
- `renderStatus` sets the runtime state word's whole `className` on every poll (`showStopping` does the same for Quit). Any layout class on those elements (such as `header-control`, which gives header buttons their 38 px height) must be part of that string, or the next poll drops it; this once shrank the old status pill.
- Runtime update checks use the stored GitHub CLI account, not shell token overrides. Finder's PATH includes common CLI locations. Missing authentication or repository access leaves lifecycle actions available and displays a check error.
- A GitHub UA release alone is not an installable desktop update: the desktop repository's reviewed lock must authorize the latest stable version and exact source identity. Maintain that feed with future releases. Saved runtime selections live outside `/data` and survive app replacement; incompatible future host profiles require an explicit migration.

- Windows development builds require Docker Desktop in Linux-container mode. Canonical paths may begin with `\\?\`; normalize only Docker arguments and keep filesystem validation canonical. UNC and WSL network-share workspaces are intentionally unsupported.
- Linux requires a graphical desktop and an initialized, unlocked Docker credential helper. GNOME may need an AppIndicator extension to display the tray. Reopening the launcher restores the hidden control window without depending on the tray.
- Creating a WebView2 window from a synchronous Tauri command, tray/menu handler, or event handler deadlocks on Windows: `WebviewWindowBuilder::build` re-enters the message loop and `CreateCoreWebView2Controller` never completes. The blank embedded window, unresponsive Status buttons, and the Stop progress bar that animates forever are all one blocked message thread. Open windows from `async` commands and worker threads only, and keep the click handler trivial. See [WRY 583](https://github.com/tauri-apps/wry/issues/583).
- Windows and Linux installers are platform-native CI outputs. A build succeeding does not validate Docker Desktop virtualization, host folder sharing, or interactive sign-in; run `docs/PLATFORM_TESTING.md` on each target machine.

- WebKitGTK defaults to suppressing script-created popups before the native callback. Runtime webviews explicitly allow them, with all URL and capability checks retained. This is exercised by the native Linux popup probe.

- Cargo examples do not receive Tauri's application resources on Windows. The popup probe imports Common Controls v6 functions and exits before main with `0xc0000139` if its activation manifest is missing. `src-tauri/build.rs` embeds the v6 dependency for MSVC examples; verify the actual probe in a signed-in Windows session.
- Key-based Windows SSH sessions cannot necessarily unlock Docker Desktop or GitHub CLI credential storage. A failed credential lookup over SSH does not prove the desktop account is signed out. Run authenticated builds and GUI tests under the signed-in account through its foreground runner or an interactive scheduled task. Keep tokens out of command arguments and build logs.

## Self-hosted Windows script policy

Windows PowerShell may default to Restricted execution policy even when the runner starts successfully. The manual Windows workflow uses `-ExecutionPolicy Bypass` for its own PowerShell process so GitHub's generated step scripts can run. It retains terminating-error behavior and explicit native exit-code checks, and does not change the machine or user execution policy.

The GUI probe timed out on deferred popup navigation when launched directly by the runner, while the same binary passed as a normal interactive user. The Windows workflow uses a temporary, limited-privilege interactive task under the runner account for this probe. Keep that account signed into the desktop. The task is removed afterward; unit tests and packaging run directly in the runner.

- On persistent runners, installing a Rust target for `1.95.0` does not install it for a separately named `stable` toolchain. Set `RUSTUP_TOOLCHAIN=1.95.0` for direct universal builds.
- Local workflows require the installed cleanup hooks. A label alone does not make a runner ready. Hooks use system Python and RTK outside the disposable work directory. See `docs/LOCAL_CI.md`.
- The local Linux builder uses Ubuntu 24.04. Its packages have that userspace baseline; Ubuntu 22.04 package compatibility is not verified.

- Cargo registry paths on Windows can exceed MAX_PATH. CI cleanup uses extended Windows paths in its Python helper; PowerShell 5 `Remove-Item -Recurse` can fail partway through these trees.
- GitHub limits Actions artifact storage by GB-hours accrued over the month, shared by every repository in the organization, not by what is stored right now. The free plan's 500 MB is about 372 GB-hours in a 31-day month. In October 2026 uploads failed with "Artifact storage quota has been hit" while only about 160 MB was stored, and deleting artifacts or GHCR images did not clear it. GHCR container images do not count at all. Each main-branch build uploads about 0.6 GB of installers, so seven-day retention alone used more than the free amount. Artifacts now expire after three days and the organization has a payment method for overage. `gh api "/organizations/enzimo/settings/billing/usage?year=YYYY&month=M"` shows usage per repository.

## UA 0.6+ host contract (contract 3)

- UA 0.6.0 replaced the single `/data/workspace` with `control/`, `dbs/`, `state/`, `runtime/` and `workspaces/{users,team,agents}`. Any file in `/data/workspace` makes UA refuse to start with `legacy_instance_layout_present`, so contract 2's folder mount there broke startup. Contract 3 mounts the chosen folder at `/data/workspaces/team/team-shared`. Never mount anything outside `/data/workspaces/`; agents cannot reach it and it can collide with UA's private areas.
- Runtime approval checks the published image against the current launcher contract on native AMD64 and ARM64. Run `tests/runtime_import_smoke.py <version>` to reproduce a failure; internal source-file changes alone do not require manual approval.
- A private GitHub repository answers "Not Found (HTTP 404)" to a token that cannot see it, the same answer as for a missing file. The compatibility list check first confirms the token can read UA, so an expired or under-permissioned `UA_READ_TOKEN` is reported as an access problem, not as a changed contract file.
- A refused UA start exits non-zero and `--restart unless-stopped` loops it. Docker then reports `Running: true`, `Restarting: true`, and keeps the last `ExitCode` until the next start. UA's own restart after first-time setup exits 0, so only a non-zero exit while restarting means failure. `RestartCount` alone cannot tell the two apart.
- UA's agent shell and Python tools require a Landlock sandbox by default. With Docker's default seccomp profile it works on Colima 0.10 (Ubuntu 24.04 VM, kernel 6.8, Landlock ABI 4) and Docker Desktop on Windows (WSL2 kernel 6.18, ABI 7), including writes into a host folder mounted inside the team folder. A kernel with ABI below 4 cannot block network access, and UA then refuses agent code for people who blocked internet access. Re-check new Docker VM kernels with UA's `custom_tools/code_sandbox.py` (`code_sandbox_status()` and `prepare_sandboxed_command`).
- Colima mounts only the user's home folder by default. A bind mount from elsewhere does not fail: Docker creates an empty folder inside the VM, so agents see nothing and their writes never reach the host.
- Over SSH, the build Mac and Windows hosts cannot use Docker's stored GHCR login. The Mac's `credsStore: desktop` points at a Docker Desktop helper that is not installed, and Windows `wincred` needs the signed-in logon session. Public images pull with a temporary `DOCKER_CONFIG` containing `{"credsStore":""}` on macOS. Windows Docker Desktop still selects a helper over SSH; use an image already on the daemon or the interactive runner.
- Apple Command Line Tools 27 `strip` damages proc-macro dylibs: macOS release builds then fail with `can't find crate for thiserror_impl` or dyld's `mis-aligned LINKEDIT string pool`, while debug builds and tests pass. The workspace sets `[profile.release.build-override] strip = false`; do not remove it until a clean `--target universal-apple-darwin` release build passes without it. The shipped application binary is still stripped.
- Returning an error from Tauri's `setup` hook does not show anything to the user. Tauri panics inside the macOS launch callback, which cannot unwind, so the app aborts with a crash report (`panic_cannot_unwind` under `did_finish_launching`) and the reason only reaches the desktop log. `setup` must always return `Ok`; startup errors go through `report_startup_failure`, which shows a native dialog and exits once it is dismissed.
- Removing Docker Desktop leaves `"credsStore": "desktop"` in `~/.docker/config.json`, and often dangling `/usr/local/bin/docker-credential-*` links. Docker asks that helper before every pull, including public images, so every download fails with `error getting credentials`. The host checks that the configured helper program exists before pulling and shows the fix; it never edits Docker's config. Over SSH the macOS Keychain helper also fails ("current session does not allow user interaction") even when configured correctly; that is a session limit, not a misconfiguration.
- On the Mac build host, installing `docker-credential-osxkeychain` (Homebrew `docker-credential-helper`) made every CI job's `docker login` fail with "User interaction is not allowed": a job's Docker config names no helper, so Docker picks the Keychain helper on `PATH`, and the runner service cannot open the Keychain. UA's publishing jobs now write `{"credHelpers": {"ghcr.io": ""}}` into their own job Docker config before logging in (UA commit `b2b72a76`), which turns the automatic choice off and keeps job logins in the disposable folder. Any job here that logs in to a registry on the Mac runner needs the same step. Desktop use of the Keychain helper is unaffected.
- A CSS `filter: blur()` on a canvas spreads past the canvas box, but WebKit (macOS WKWebView) repaints only the box when the canvas drawing changes, so the spilled blur stays on screen as a stale shadow. WebDriver screenshots re-render the page and never show it, so the intro title looked clean in automated captures while users saw a faint frame around the word. Blurred canvases in `intro_word.js` therefore carry a transparent margin of three blur radii.
- Apple Command Line Tools 27 `lipo` rejects `lipo <file> -verify_arch arm64 x86_64` with "-verify_arch requires exactly one input file", so the macOS CI step that checks for a universal binary failed after a successful build. CI now compares `lipo -archs` output instead.
- Windows Smart App Control can switch itself on after its evaluation period and then blocks every program Cargo compiles and runs (`An Application Control policy has blocked this file. (os error 4551)`), so Windows CI fails before any test runs. It must stay off on the Windows runner; see [Local CI](docs/LOCAL_CI.md#windows-and-wsl).
- Personal details reached tracked docs and commit metadata (runner and host names, host accounts, Actions run links, a personal email as commit author), and the only full fix was deleting and recreating the GitHub repository, because pull requests keep old commits reachable after a force-push. Actions run logs name the self-hosted runner hosts and their folders, so a run link points readers at host details too. Describe runs and hosts generically, keep host notes outside the repository, and commit with a noreply address; `scripts/check_personal_details.py` (run by the Git hooks and the **Personal details** workflow) and `CONTRIBUTING.md` ("Personal details") enforce what a pattern can catch.
- When UA's repository was recreated in October 2026, its image package was recreated too, so the digests listed for UA 0.8.5 and 0.9.0 to 0.9.3 in `compatible-runtimes.json` returned "not found" from the registry. The launcher could still offer those versions, but downloading one failed, and an install still running one keeps working only until something pulls its image again. The entries were removed (the one exception to the append-only rule), leaving UA 0.9.4. Before deleting image versions, release a desktop build that pins a surviving image, remove the deleted versions from the list, and tell users in the release notes.

- Comparing whole UA source files blocked compatible releases after internal build or sign-in locking changes. Compatibility approval now runs the locked desktop behavior against the published image on native AMD64 and ARM64. Keep release identity checks ahead of image execution, and make failed or unavailable probes fail the workflow.
- A synthetic Codex import test must isolate its home directory. UA may otherwise find the host's existing sign-in after rejecting the synthetic source, making an invalid-file test pass for the wrong reason. One-shot helpers use disposable data, a private test home and no network.

- A restricted Colima profile may not share the runner's home directory. Docker's `--volume` silently creates a directory for a missing bind source, so a synthetic `auth.json` can become a directory in the image. Runtime checks seed their synthetic source into an owned Docker volume through stdin and mount that source read-only for import.
- Docker internal bridge networks do not publish container ports. Host connectivity checks use a disposable standard bridge with loopback-only publications; one-shot helpers still use `--network none`.
- On Python 3.12, recursive cleanup reports files that disappear after directory enumeration. A cancelled test process can remove its temporary lock during shutdown. The shared hook accepts that already-removed file, but retains the job manifest when an entry still cannot be deleted.
- An `always()` merge-summary job can survive workflow cancellation while queued, holding the concurrency slot and delaying a newer commit's checks. The compatibility merge job runs only after successful native checks on a release-entry branch. Failed checks already explain their reasons in their own summaries.
- Native Windows debug tests, lint and popup checks can consume 45 minutes before the separate optimized application build finishes. Its job has a 90-minute budget so a successful test run is not cancelled during the required build; Linux keeps its 45-minute limit.
